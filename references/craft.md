# 做长片、做高质量片的硬经验

这份是补 `engine.md`（API）和 `visualization.md`（讲解设计）的：那些是"怎么调用""该画什么"，
这份是**做 90–150 秒的片子时，哪些写法会救你、哪些写法会坑你**。
每一条都是在真片里踩过或验证过的。新片开工时照着过一遍，比事后返工省时间。

---

## 〇、先定两件事，再写代码

1. **一张时间轴表**。所有章节的进出时刻集中写在一个 `T = {}` 里（`ch1In: 16.4, ch1Out: 32.2 …`），
   正文里一律引用 `T.ch1In`，不写裸数字。改一处就能挪动整章，不会出现"挪了画面忘了挪字幕"。
2. **一把贯穿全片的尺子**。参考片每片都有一个从头到尾复现的仪表/计数器：
   《超常刺激》是"本能读数"表盘，《信息论》是刻度上的光点。
   你这支片的尺子是什么，先想清楚——它让散落的例子变成"同一个量被量了好几次"。
   没有尺子，长片会散成一段段互不相关的插画。

---

## 一、时间：子段一律用 `fade()`，不要用 `ss()`

这是最容易踩、也最难查的坑。

- `ss(t, a, b)` = `smooth(seg(t,a,b))`，**t 超过 b 之后恒等于 1**，永远不退。
- `fade(t, a, b, fin, fout)` = 到 a 用 fin 秒亮起、到 b 前 fout 秒暗下，两头都收。

所以：

| 用途 | 用 |
|---|---|
| "从这一刻起一直存在到片尾" | `ss` |
| 一章里的一个子镜头、一句标注、一次计数、一个道具 | **必须 `fade`** |
| 一堆东西**依次出现**（错峰 / stagger），出现后要一直留着 | **`ss`**（不是 `fade`） |

写错了的典型症状：某一章里明明该消失的东西一直挂在屏幕上，而且越往后叠得越多。
自查方法：截每一章最后 0.5 秒的静帧，看屏上是不是只剩下该留下的。

**反向的坑（两个方向都踩过）**：写"错峰依次出现"时很容易顺手写成 `fade`——
```js
const kx = fade(t, 60.0 + i * .34, 60.5 + i * .34, .4, .02);   // ❌ 第 i 个元素在 60.5s 就归零了
const kx = ss(t, 60.0 + i * .34, 60.5 + i * .34);              // ✅ 淡入后留住
```
因为 `fade` 的窗口只有 `b - a` 这么长（这里是 0.5 秒），元素淡入完立刻就淡出了。
一整排围观者、一排亮起的窗、五步链的每个格子、几只齿轮——**凡是"一个个冒出来"的，都要 `ss`**。
这个 bug 看不见报错、画面也不崩，只是元素从来没出现过，只能靠像素探测抓。

```js
const kHit = fade(t, 41.1, 41.9, .08, .08);     // 一次撞击：亮起、停留、收掉
const kNote = fade(t, 45.4, 49.8, .8, .4);      // 一条标注：慢慢来，快快走
```

## 二、反复发生的动作：写成"事件数组 + 一次采样"

不要写 `if (t > 18 && t < 19) … else if (t > 24 …)`。把事件列成数组，再写一个函数按 t 求值。

```js
const TRIALS = [[18.0, 19.1, 23.0], [24.0, 24.9, 28.4], [29.4, 30.2, 32.4]];   // [开始, 成功, 结束]
const onOff = (t, L) => L.reduce((m, tr) => Math.max(m, fade(t, tr[0], tr[2], .07, .07)), 0);
const escN  = TRIALS.filter(tr => t >= tr[1]).length;                          // 计数器直接用
```

好处：挪动一轮只要改数组里三个数字；计数、累计、动画全部自动跟着走。

## 三、连续量：要先算成数组，再按 t 取

累积曲线、进度条、任何一种"随历史增长"的东西，都是 `seek(t)` 的纯函数——
所以必须**从 0 重算到 t**，不能靠"上一帧的值"。做法：在模块作用域把整条曲线按固定步长采样成数组，画的时候按 t 取前 N 个点。

```js
const CUM = (() => { const out = []; let y = 0;
  for (let i = 0; i * .05 <= 100; i++) { const tt = i * .05; if (pressed(tt)) y += 1; out.push([tt, y]); }
  return out; })();
// 画的时候：取 t 之前的点，用 fr.poly(..., { k: 生长进度 }) 让线长出来
```

`fr.poly(pts, { k })` 的 `k`（0–1）是"线长到哪儿"，用来做生长的线。`fr.ellipse(..., { a0, a1 })` 画半弧、`dash: [a,b]` 画虚线轨迹，配 `poly` 就够画"本来可以走但没走的那条路"。

## 四、`fr.g()` 的四种进阶用法

```js
fr.g({ clip: [x, y, w, h] }, fn)      // 裁切：做手机屏里的滚动信息流、窗口里的东西
fr.g({ s: [sx, sy] }, fn)             // 非等比缩放：翻牌（sx 从 1 → -1 → 1）、挤压、拍扁
fr.g({ at: [x, y], rot, s }, fn)      // 组合变换：一个角色/道具的整体位姿
fr.g({ a, add: true }, fn)            // 加法混合：辉光、光点、拖尾
```

- **滚动列表**：外层 `fr.g({ clip })`，内层按 t 平移一整列元素。元素位置用 `rng(seed)` 一次性生成好（确定性，见下）。
- **翻面**：`fr.g({ s: [Math.abs(1 - 2*k) , 1] })` —— k 从 0 到 1，横向先压扁再展开，视觉上就是翻过去。

## 五、随机只能来自 `rng(seed)` / `hash(n)`

`Math.random()` 会让 `--det` 自检失败，也会让并行渲染（`--jobs`）各段的画面不一致。
需要一堆随机位置时，在模块作用域一次性生成：

```js
const FEED = (() => { const r = rng(3); return Array.from({ length: 26 }, () => ({ x: r(), k: r() })); })();
```

## 六、逐字：关键词高亮用 `fr.chars` + 标记

字幕里 `{词}` 是金、`{!词}` 是红——`K.subs` 已经处理。正文里的字要逐字控制时自己调：

```js
fr.chars(str, x, y, { font: 'sansh', size: 64, track: 6, color: INK },
  i => ({ a: smooth(seg(t, t0 + i * .07, t0 + i * .07 + .16)) }));
```

`K.parseMark(s)` 可以把带标记的字符串拆成 `[{ch, tone}]`，自己做高亮时用它。

## 七、转场：章与章之间整幅暗一下

```js
const DIP = [8.0, 16.2, 32.2, 50.2, 66.2, 79.2, 94.2];
const dim = lerp(.16, 1, K.dips(t, DIP, .42));
fr.g({ a: dim }, () => { /* 本章内容 */ });
```

`K.dips` 在给定时刻附近把亮度压到 0；用 `lerp(.16, 1, ...)` 而不是直接乘，是留一点底，不至于死黑。
**片名卡除外**——它自己带压暗和金屑，不要再叠一层 dips。

## 八、声音：事件表 + 一次合成

画面里只管登记时刻：`fr.sfx(41.6, 'rise', {})`。然后

```bash
python engine/render.py <工程> --events     # → audio/events.json
python engine/audio.py <工程>               # → audio/sfx.wav
python engine/audio.py <工程> --bgm 曲子.mp3 -8
```

名字只有这几个：`tick soft chord bloom rise thud tock stamp shimmer hush flash`。
一次动作的"点"和它的"尾音"要分开登记（比如撞击 `thud` 在接触那一帧，余响 `hush` 在 0.4 秒后）。

## 九、长片的渲染顺序（别一上来就渲全片）

```bash
python engine/render.py <工程> --sheet 20        # 全片均匀取 20 帧拼一张，先看整体
python engine/render.py <工程> --motion 42.4 44  # 看某一段的动作和转场
python engine/render.py <工程> --jobs 4          # 全片，分 4 段并行（100 秒约 3–6 分钟）
python engine/render.py <工程> --events && python engine/audio.py <工程>
python engine/render.py <工程> --det             # 确定性自检，提交前跑一次
```

`--sheet` 是最便宜的 QA：20 帧就能看出"有没有一章是空的""字幕有没有压住东西""某个道具是不是一直在屏上没走"。

## 十、动工前先看这几个毛病

对照 `visualization.md` 第八节逐条查之外，这几条是长片特有的：

- 一章里有没有**至少一秒的纯画面**（没有字幕，让画面自己说完）？全程字幕打满会闷。
- 有没有**回场**：开头那个道具/角色在结尾回来一次？这是"收束感"的来源。
- 有没有**一处只上字**：一句结论单独占满一屏，什么都不画？长片需要这种呼吸。
- 每章的最后 0.5 秒是不是干净的（见第一条的 `fade` 自查）？
- 关键帧放大到 100% 看字的边缘：辉光 `glow` 开太大字会发白，"发白"是这一整套观感里最大的忌讳。

## 十一、概念章要铺一块"舞台板"

实景章（房间、实验室、街景）自己就是满的；**概念章**（只有牌、格子、箭头、公式这些东西）如果直接摆在
`backdrop()` 上，整章亮度会掉到 40 出头，看着像没做完。做法是先铺一块底板，再把东西摆上去：

```js
function stage(fr, x0, y0, x1, y1, a, c) {
  fr.g({ a }, () => {
    fr.rect(x0 + 12, y0 + 16, x1 - x0, y1 - y0, { r: 18, fill: '#000', a: .36 });   // 投影
    fr.rect(x0, y0, x1 - x0, y1 - y0, { r: 18, fill: c || '#414757' });
    fr.rect(x0, y0, x1 - x0, 7, { r: 4, fill: '#6C7488', a: .55 });                 // 一道亮边，板子才有厚度
  });
}
```

亮度参照（全片逐秒平均，PIL 量的）：实景章 85–90，概念章铺板后 60–64，卡片章 70–80，
片名卡 18（它自带压暗，不要再加东西）。**低于 45 的章要怀疑是不是少铺了板。**

QA 做法（模型看不了图，只能数像素）：
```bash
python engine/render.py <proj> --stills 21 34 47 55 62 72 82      # 每章取一帧
python -c "from PIL import Image; ..."                            # 算全帧 mean RGB 和亮度
```
一章一帧不够，成片后从 `renders/raw.mp4` 按 `fps=1` 抽 100 帧扫一遍亮度曲线，能抓出"哪一章整体发黑"。

## 十二、环境坑

- **页面一直 `READY !== true`，然后超时**：九成是 `engine/fonts/` 里的字体 404（`@font-face` 加载失败，`document.fonts.ready` 直接 reject）。
  跑 `python engine/get_fonts.py` 补字体；`--check` 只检查不下。
- 中文字体各 20MB，仓库可以不带，装好 skill 后跑一次下载脚本。
- Windows 上 `git add` 报 CRLF 警告是正常的，不影响。
- 并行渲染（`--jobs`）必须保证画面是 t 的纯函数——任何跨帧状态都会让各段接不上。
